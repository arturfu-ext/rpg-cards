# Golden-master fixtures

Parity test data for the TypeScript port of the legacy card engine
(`generator/js/cards.js`). The harness feeds each deck/options combination
straight into `card_pages_generate_html` and compares the output
byte-for-byte against the captured legacy output.

## Layout

- `decks/` — input decks (arrays of card objects, same shape as saved deck JSON):
  - `sample-deck.json` — the stock example deck (`generator/data/card_data_example.js`) as plain JSON.
  - `all-directives.json` — exercises every directive in `card_element_generators`,
    including empty/missing-param variants, inline `<icon>` tags, unknown
    directives, and all card-level fields (icons, containers, rotation,
    background image, header/title overrides, font sizes, counts).
  - `layout-matrix.json` — 7 simple cards with counts [1,2,1,3,1,1,2]
    (11 cards total) so pages do not fill evenly, exercising repeats and the
    empty-card padding path.
- `options/` — FULL `CardOptions` objects (no default merging happens in the
  harness). Each file is `default_card_options()` with the variations its
  name describes (arrangement, bleed, crop marks, page geometry, zoom,
  per-deck defaults, card_count override).
- `fixtures/` — captured legacy engine output, generated by
  `pnpm golden:capture`. **Do not hand-edit.**

## Contract

The files under `fixtures/` are the frozen parity contract: the TypeScript
engine must reproduce them byte-for-byte for every deck x options pair. If a
deliberate behavior change is ever made, regenerate them with
`pnpm golden:capture` and review the diff carefully.
